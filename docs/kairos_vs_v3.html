第二部分 · Kairos Code 优缺点 (R38.6.4 后)

维度 ✅ 优势 (vs 其他 6 款) ❌ 短板 (vs 其他 6 款) 改进优先级
易用性
  • 2 栏 UI (sidebar + chat),没有 Workbench 多 tab 干扰
  • Web UI 简单,功能全在 chat 消息流里
  • Settings 缩到 3 tab (Provider/Mode/About)
  • 无 CLI 学习曲线,直接点
  • 没有 OpenCode 那样的 inline 编辑器
  • 没 Prime Agent 的 /goal /autonomous CLI 命令(只有 API)
 P1
多 Agent 协同
  • async subagent handle (借鉴 Prime) — 父 Agent 不阻塞
  • subagent_status / subagent_cancel API 可轮询
  • Coder ↔ Reviewer 内置双 Agent 循环
  • 没 Hermes/OpenClaw 那样的子 Agent 跨会话消息
  • 子 Agent 不能持久化跨天会话
  • 没 Prime Agent 的 IPython REPL,工具调用是一次性 JSON
 P1
长任务
  • /goal 持久目标 (借鉴 Prime) — 跨回合不丢
  • /autonomous 预算模式 (借鉴 Prime) — turn/token/time + quality gate
  • Auto checkpoint 每文件编辑前
  • Compaction 每 10 轮自动
  • 没 Prime Agent 的 Daemon 模式 — 浏览器关就停
  • LongRunningRegistry 进程内 dict,重启后 handle 失效
  • autonomous 提交后无 background worker 自动消费
 P0
模型灵活性
  • 17 个 LLM provider 预设 (含 MiniMax、Qwen、GLM、Mistral、xAI 等)
  • 完整 OpenAI 兼容协议 + Anthropic 兼容协议
  • 模型字段填错也能跑 (fallback to default),不锁用户
  • 没 Codex 那种 provider 强校验
  • 需要用户自己懂 model id 命名
 P2
工具 / 扩展
  • 21 个 MCP server 预设 (含 context7、playwright、postgres、redis)
  • 20 个 plugin 预设 (Anthropic + EveryInc + wshobson)
  • 43 个 skill 预设 (Anthropic + obra + community)
  • 38 个 borrowed REST endpoint
  • 没 OpenClaw / Hermes 的 skill 自动创建
  • 需要用户手动跑 install script
  • UI 不显示 MCP/plugin 列表 (高级功能靠 API)
 P2
记忆 / 自改进
  • FTS5 跨会话记忆,自动注入 Coder system_prompt
  • Memory 4 op API (remember/recall/forget/list)
  • Auto checkpoint 写文件前快照
  • 没 Prime Agent 的 Continual Harness — Agent 不能 CRUD 自己的 prompt/skill
  • 没 Hermes 那样的自学习循环 (Agent 不会自动改进自己)
  • Memory 不会被 LLM 主动管理 (只通过 API)
 P1
安全 / 沙箱
  • 3 档 sandbox policy (off/standard/strict)
  • real-time deny-pattern 拦截 rm -rf /
  • Backend terminal tool 自带 25+ deny patterns
  • 没 Prime Agent 那样的 worker / kernel 进程隔离
  • 在 Windows / 非 Linux 跑没 Landlock 之类 OS 级沙箱
  • 用真 OS 权限跑 LLM 生成的代码,风险大
 P1
性能 / 跑分
  • 对话 / 简单任务非常快 (intelligent intent classification)
  • MAX_TOOL_TURNS=200 (Prime Agent 25 限制早已移除)
  • ARC-AGI-3 95.5% (Prime Agent) 远超我们 (我们没公开 benchmark)
  • Prime Agent 的 95.5% 来自 harness 工程优化,模型能 clone 这套
  • DeepSeek Harness 这类竞品在 ARC-AGI-3 上 >90%
 P0
跨天续跑
  • /goal 让目标跨回合持久
  • Auto checkpoint 让文件改动可回滚
  • Compaction 让上下文跨长任务不爆
  • 没 Prime Agent 的 Daemon 后台 worker
  • 浏览器关 = agent 停 (关键短板)
  • long_running 是进程内 dict,重启失效
 P0
开源 / 可审计 闭源 / 模型厂商旗舰 Kairos Code (本项目)
评级: P2 优势 可长期保持 · P1 短板 应在下个 sprint 修 · P0 关键 必须尽快修
关键 P0 结论: ① Daemon 后台 (学 Prime Agent)— 浏览器关也能继续跑 ② Arc-AGI 跑分 baseline (学 DeepSeek/Prime)— 公开 harness 优化 ③ autonomous worker — 后台消费 job queue
